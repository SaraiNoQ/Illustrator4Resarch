# Visual QA and revision

A successful plotting script is an intermediate result. Completion requires
inspection of the exported figure.

## QA sequence

1. Run the plotting script from a clean process.
2. Validate the Figure Spec.
3. Run deterministic export checks.
4. Create an original-plus-grayscale review image.
5. Open or read the review image with the runtime's image inspection tool.
6. Write an issue list classified as correctness, legibility, hierarchy,
   accessibility, or polish.
7. Fix actionable issues and repeat the render.
8. Stop when the acceptance criteria pass or a scientific decision requires the
   user.

Do not claim that visual QA passed when the image was never inspected.

## Deterministic checks

Use:

```bash
python scripts/validate_figure.py \
  --spec figures/main.spec.json \
  --report figures/main.qa.json
```

The validator checks file presence, signatures, dimensions, encoded raster DPI,
blank or near-uniform output, tonal contrast, crop-boundary risks, and excessive
blank outer margins. These checks catch export failures and obvious canvas
waste but cannot judge scientific communication.

Generate a review image:

```bash
python scripts/render_preview.py \
  figures/main.png \
  --output figures/main.review.png \
  --grayscale
```

## Visual checklist

### Correctness

- Every expected method, condition, data point, and panel appears exactly once.
- Axis labels, units, legends, uncertainty, and captions match the data.
- The direction and scale do not exaggerate or reverse the intended comparison.
- No transformation, sorting, aggregation, or omitted value is undisclosed.

### Legibility

- Text is readable at the target paper column width, not only when zoomed in.
- Tick labels, annotations, panel labels, and legends do not collide or clip.
- Dense value labels are removed or selectively retained.
- Lines, markers, hatches, and error bars remain distinguishable.

### Hierarchy

- The intended scientific message is discoverable within a few seconds.
- Proposed and baseline methods are emphasized consistently but not
  manipulatively.
- Colors and markers encode named semantic roles; they are not an unexplained
  collection of attractive swatches.
- Dense method families have visible grouping, spacing, or separators when the
  labels alone are slow to scan.
- Gridlines, borders, annotations, and decoration do not compete with the data.
- Multi-panel order follows the narrative.

### Accessibility

- Grayscale preview preserves important distinctions.
- Color is not the only encoding when methods may collide in grayscale.
- Categorical, sequential, diverging, and cyclic palettes match the data role.
- Text and marks have usable contrast against the background.

### Polish

- The exported artboard hugs the outermost title, label, legend, and mark with
  small deliberate padding; an `outer_whitespace` warning is fixed unless the
  confirmed design intentionally needs that margin.
- Whitespace inside the composition and aspect ratio fit the target venue.
- Panel sizes, baselines, legends, and typography are consistent.
- Raster borders and backgrounds are coherent.
- The result looks intentional at final export size.

Passing collision and crop checks is not enough. Compare visual weight across
titles, labels, grids, highlights, and marks, and ask whether the figure looks
like one coherent composition rather than several default axes placed beside
each other.

## Revision policy

Normally perform up to three render-review passes:

1. Correctness and structure.
2. Legibility, hierarchy, and accessibility.
3. Final polish.

Do not make arbitrary style churn after the acceptance criteria pass. Continue
beyond three passes only when a clear, safe fix remains. Ask the user when the
remaining issue depends on scientific intent, not taste.

For Matplotlib exports, prefer the bundled `finalize_figure(...)`. Otherwise use
one layout engine and save PNG/PDF with `bbox_inches="tight"` and roughly
`0.02`–`0.05` inches of padding. Do not remove whitespace by clipping labels or
shrinking typography below the confirmed final-size requirement.

## QA report

Store deterministic checks in the JSON report generated by
`validate_figure.py`. In the final response, add:

- number of visual review passes;
- visual issues fixed;
- unresolved limitations;
- whether review included the grayscale preview;
- any assumptions that still require user confirmation.
